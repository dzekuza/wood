# Utils Catalog

Pure helpers in `src/utils/`. A util is pure, typed, and unit-testable; anything
with I/O or client state belongs in `lib/` or a hook instead.

| Util | File | Signature | Purpose |

| `buildLocalFilters` / `applyLocalFilters` | `app/lib/collectionFilters.ts` | `(products: T[]) => Filter[]` / `(products: T[], searchParams) => T[]` | Used only by `collections.all.tsx` — computes Availability/Price facets and filters the fetched product array in JS, since the top-level `products` Storefront query has no server-side `filters` argument. Shaped as the same `Filter[]`/`ProductFilter` types the real per-collection filters use so `CollectionFilters` doesn't need to know which page it's on |
| `getSwatchTone` | `app/lib/swatches.ts` | `(name: string, color?: string \| null) => string` | Maps a variant option's name/color to a `.product-swatch-tone-*` CSS class for swatches with no image. Shared by `ProductForm` (PDP option picker) and `ProductItem` (card grid) so both render color-only swatches identically — extracted from a PDP-only helper when the card grid needed the same logic |
| `getSwatchTexture` / `isHardwareColourOption` | `app/lib/swatches.ts` | `(name: string) => string \| undefined` / `(optionName: string) => boolean` | `getSwatchTexture` maps a timber-finish value name to one of the `public/demo/texture-*.jpg` grain crops (the PDP swatch tile's image, see [[components/common\|ProductForm]]); `matchFinish` tries the longest names first so "Light Grey" isn't swallowed by "Grey". `isHardwareColourOption` (`/hook\|handle\|hardware\|bracket\|fixing\|knob\|hinge\|rack/i` — `rack` is in there because the coat racks call their metal option **Rack Colour**, their timber one being Oil Colour) is the **opt-out**: a Hook/Bracket Colour option is still a colour option, but its values name metals, so `ProductForm` withholds the texture fallback and lets `getSwatchTone`'s metal branches (brass, antique brass, copper, chrome, pewter — matched before the timber words) supply a flat chip |
| `isSliderOption` | `app/lib/productOptionDisplay.ts` | `(optionName: string, overrides?: string[] \| null) => boolean` | Gates which non-swatch PDP option renders as the length slider vs. the dropdown in [[components/common\|ProductForm]]. `overrides` (when non-empty) fully replaces the coded default `SLIDER_OPTION_NAMES` (`['Length']`) — exact, case-insensitive name match either way, **with "lenght" treated as "length"** (2026-10-13: options were renamed "Beam Lenght" → "Beam Length" while the metafields kept the old spelling, which silently turned three mantel-beam sliders back into dropdowns). `overrides` is the product's `custom.slider_options` metafield, merchant-editable per product on the product edit page in Shopify Admin — see [[../meta/decisions-log#ADR-0013\|ADR-0013]]. Added 2026-09-10 to replace a substring match on "length"/"lenght" that mis-fired on compound dimension options like "Mantle Beam (... x Lenght)" |
| `compareBySize` | `app/lib/productOptionDisplay.ts` | `(a: string, b: string) => number` | `Array.sort` comparator for a size-like option value string ("15cm x 60cm", `4"x4"`): pulls every number out left to right and compares them in order (depth before length), so "20cm x 60cm" sorts before "15cm x 70cm". Returns `0` (no reorder) if either string has no number. Added 2026-10-30 — Shopify Admin's option-value order is creation order, not size order, which left the console "Depth x Length" dropdown scrambled; applied to both the dropdown and the slider's value list in [[components/common\|ProductForm]] |

| `buildHomeContent` | `app/lib/homeContent.ts` | `(data: HomeContentQuery \| undefined) => HomeContent` | Merges the homepage `home_page` metaobject response over `HOME_CONTENT_DEFAULTS`, field by field — see [[homepage-content]]. Blank and missing fields both fall back (`text()` trims, so clearing a field in admin restores the coded default rather than rendering an empty heading); multi-line headings split on `\n`; an unrecognised process-icon key falls back to that step's positional default. Pure and covered by an assertion pass over a mocked response |

| `currencyOptions` / `activeCurrency` / `resolveCountry` | `app/lib/localization.ts` | `(localization: Localization) => CurrencyOption[]` / `... => CurrencyOption \| null` / `(value, available) => CountryCode` | Back the header [[components/common\|CurrencySwitcher]]. `currencyOptions` dedupes `availableCountries` down to one entry **per currency** (GB and LT both settle in EUR on this shop, so a per-country list would repeat EUR). `resolveCountry` is a guard, not a convenience: an unsupported market makes every subsequent Storefront query throw, so a posted value is narrowed against `availableCountries` before it reaches the session — see [[../meta/decisions-log\|ADR-0009]] |
| `formatReviewCount` / `RatingSummary` | `app/lib/reviewStats.ts` | `(count: number) => string` | `1400` -> `1.4k`. | `shouldHideCollection` / `compareCategories` / `getPagePath` | `app/lib/site.ts` | `({handle, title}) => boolean` / `(a, b: SortableCategory) => number` / `(handle: string) => string` | `shouldHideCollection` filters merchandising/utility collections (`most-popular`, room-name leftovers) out of anywhere that enumerates collections — the header search tags and the category lists. `compareCategories` is the one comparator for every category list (homepage grid, Categories page, shop sidebar): the collection's `custom.sort_order` metafield first (lowest first, unset last), then `HOMEPAGE_CATEGORY_ORDER`. Every category query must select `sortOrder: metafield(namespace: "custom", key: "sort_order") { value }`. See [[../meta/decisions-log#ADR-0015]] |
| `resolveSelectedOptions` / `cheapestAvailable` / `unitFromSearchParams` | `app/lib/variantSelection.ts` | Picks the PDP's opening variant: `?variant=<id>` or option params (matched in cm or inches via `formatMeasurement`), else the cheapest available variant. **2026-10-30: once the URL names every option, the picked values are passed straight through instead of being matched against the loader's own `variants(first: 250)` list** — see [[../meta/decisions-log#ADR-0025\|ADR-0025]]; that list (and its cheapest-available fallback) is now only consulted for a partial/legacy link naming fewer options than the product has. `unitFromSearchParams` reports which unit a link was written in. Used by the `products.$handle` loader. |
| `seoMeta` / `toMetaDescription` / `getCanonicalUrl` | `app/lib/seo.ts` | `({title, description?, path}) => MetaDescriptor[]` / `(...candidates) => string \| undefined` / `(path: string) => string` | Every indexable route's `meta` export goes through `seoMeta`, which emits the title, the description and a real `<link rel="canonical">` (`tagName: 'link'` — a bare `{rel, href}` renders as an ignored `<meta>`). `toMetaDescription` takes the first non-empty candidate (merchant SEO field → content → written default) and trims it to 155 chars at a word boundary. Canonicals are absolute on `SITE_DOMAIN` and **path only** — see [[seo-metadata]] |
