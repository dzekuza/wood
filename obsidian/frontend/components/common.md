# Common Components Catalog

Shared composed components in `components/common/` — built from [[components/ui]]
primitives, reused across features.

| Component | File | Purpose | Status |
|-----------|------|---------|--------|
| `Icons` (`StarFilledIcon`, `HeartFilledIcon`, `FacebookFilledIcon`, `InstagramFilledIcon`, `PinterestFilledIcon`) | `app/components/Icons.tsx` | Solid-fill SVG icons — `@tabler/icons-webfont` has no `-filled` glyphs, so any solid star/heart must come from here, not `ti-star-filled` / `ti-heart-filled` | |
| `Lightbox` | `app/components/Lightbox.tsx` | Shared full-screen image preview: arrows, counter, a click-to-jump thumbnail strip (between the image and the counter), Escape, backdrop-button dismissal. Backdrop is `rgba(28,28,28,.5)`. Portals to `document.body` — required, since callers sit inside transform-animated marquee tracks. Used by both `TestimonialsMarquee` (homepage reviews) and `ReviewsSection` (product-page reviews) — `ReviewsSection` used to have its own single-image `ImageLightbox`/`.rev-lightbox-*` with no nav; unified onto this component so both surfaces behave identically | |
| `Header` / `HeaderMenu` | `app/components/Header.tsx` | Site header + primary nav. **Nav items are fully Shopify-native** — `HeaderMenu` renders `header.menu.items` (the Storefront `menu(handle: "main-menu")`, fetched in `root.tsx`'s loader via `HEADER_QUERY`), not hardcoded links. A top-level item with nested `items` renders as a `.header-dropdown` on desktop (hover-reveal) and an indented flat list (`.header-menu-item--child`) in the mobile aside — Shopify's nav editor only supports one level of nesting, matching the `ParentMenuItem`/`ChildMenuItem` GraphQL fragments in `lib/fragments.ts`. `resolveMenuItemUrl()` strips the menu item's absolute `url` (myshopify domain or primary domain) down to a path so `<NavLink>` does client-side routing instead of a full page load. Editing nav = editing **Settings → Navigation → Main menu** in Shopify Admin, no code change or deploy needed — see [[../../meta/decisions-log\|decisions-log]] 2026-08-31. The `categories` (non-hidden collections) computed in `Header()` is unrelated to nav now — it's only passed to `HeaderSearch` for the "Popular Search" tags | |
| `AnnouncementBar` | `app/components/AnnouncementBar.tsx` | Top strip above the header — tagline + phone/email, rendered inside `Header` | |
| `AnnouncementBar` | `app/components/AnnouncementBar.tsx` | Top bar: socials / rotating message / contacts in a `1fr auto 1fr` grid inside `.announcement-bar-inner` (capped at 1400px to match `.header-topbar`; the band itself stays full-bleed). Messages come from `ANNOUNCEMENT_MESSAGES` in `app/lib/site.ts` and rotate every 4s (copy signed off 2026-08-31 — free delivery has no order threshold). Socials render via `SocialLinks`, not its own markup | |
| `CurrencySwitcher` | `app/components/CurrencySwitcher.tsx` | Header currency control, between the account and cart buttons. Shopify prices in whatever currency the buyer's **market** settles in, so this posts a *country* to `routes/localization.tsx` and labels it by currency. Native `<select>` submitted on change (works pre-hydration; `<noscript>` submit button as the no-JS path). Renders as a plain non-interactive label when the store has fewer than two presentment currencies — which is the case today, see [[../../backend/storefront-environments\|storefront-environments]] | |
| `SocialLinks` | `app/components/SocialLinks.tsx` | The shop's social accounts, rendered from the single `SOCIAL_LINKS` list in `lib/site.ts` so the announcement bar and the footer can never advertise different sets again (they used to: Facebook+Instagram on top, Instagram+Pinterest+YouTube below). Takes `linkClassName`/`iconClassName` because the two surfaces style their anchors differently. Adding a platform means adding it to `SOCIAL_LINKS` **and** to the `ICONS` map here | |
| `CategoriesGrid` | `app/components/CategoriesGrid.tsx` | Homepage category carousel (despite the name). Scroll-snap track at all widths; 6-up on desktop (single page, so no nav renders), 3-up under 1080px where paging kicks in, free swipe under 620px. Page count is measured from card width + gap in a `ResizeObserver` — don't swap it for a `PER_PAGE` constant, the card basis changes per breakpoint. Heading/subheading/link label come from the `home_page` metaobject via an optional `content` prop ([[homepage-content]]) | |
| `HeroCarousel` | `app/components/HeroCarousel.tsx` | Homepage hero slider; optional `rating` prop renders the `.demo-hero-rating` badge (store-wide `RatingSummary` from [[../utils\|reviewStats.ts]], passed down by `_index.tsx`'s loader — accepts `null` for a catalogue with no reviews yet). Rating/h1/blurb live in `.demo-hero-copy` (24px internal gap); `.demo-hero-content` holds the single 48px gap to the CTAs. Autoplays every 3s (`SLIDE_DURATION_MS`, mirrored by `--demo-hero-slide-duration` in `demo.css` — change both together); nav and autoplay switch off below 2 slides. **Slides now come from the `home_page` metaobject** ([[homepage-content]]) — one entry exists, so it renders single-slide; adding a second in admin restores the nav. Renders `.demo-hero-nav` as a **sibling** of `.demo-hero`, below it, not overlaid | |
| `CategoriesGrid` | `app/components/CategoriesGrid.tsx` | "Our Categories" grid — every non-hidden collection the storefront returns, with real product counts (`Category.count`). The list is **data-driven**: `_index.tsx`'s `buildCategories()` reads `collections(first: 20)`, drops anything `shouldHideCollection` matches, and orders the rest by `homepageCategoryRank()` (`HOMEPAGE_CATEGORY_ORDER` in `lib/site.ts`); a collection created in Admin shows up with no deploy, appended after the ranked handles | |
| `ProductItem` | `app/components/ProductItem.tsx` | Shared product card (`.pcard`) — homepage, collections, PDP recommendations. `.pcard-name` is clamped to **one line** with an ellipsis (titles run to ~100 chars), which also keeps every `.pcard-heading` the same height so price rows line up across a grid row. `.pcard-body` is two blocks — `.pcard-heading` (name + rating) and `.pcard-bottom-row` (price + swatches) — so the gap between "what it is" and "what it costs" is set independently of the rhythm inside each. Renders heart-save toggle, per-product star rating (via `getRatingSummary` in [[../utils\|reviewStats.ts]], parsed from the `reviews.product_reviews` metafield; a product with no reviews shows an explicit `0.0 (0 reviews)` via `.pcard-rating.is-zero`, muted so a gold star never sits beside a zero — it used to render an invisible placeholder), price, variant swatches, and a `.pbadge` (Save $X from `compareAtPriceRange`, or Sold out from `selectedOrFirstAvailableVariant.availableForSale`). Image area (`.pcard-img`) shows up to 5 `images.nodes` (featured first, deduped) as stacked `.pcard-img-frame`s crossfaded by an `.is-active` class driven by `activeImage` state; on hover (`@media (hover: hover) and (pointer: fine)`, so touch just shows the featured image) `.pcard-img-nav` fades in — chevron arrows + progress dots styled after `HeroCarousel`'s `.demo-hero-nav`, white-on-dark since the card has no strip below the image to host it in. Nav buttons `preventDefault`/`stopPropagation` so scrubbing images never triggers the card's outer `Link`. Gallery frames render via Hydrogen's `<Image>` (`sizes="(min-width: 980px) 25vw, (min-width: 640px) 33vw, 50vw"`), not a raw `<img>` — see [[../../meta/changelog|changelog]] 2026-08-31, plain `<img src={node.url}>` was pulling full Shopify source resolution per card | |
| `SearchSuggestions` | `app/components/SearchSuggestions.tsx` | Fallback panel shown when the header/aside search field is focused but empty (previously blank) — "Popular Search" tags built from `header.collections` (real collection titles, already fetched by `HEADER_QUERY`, no extra request) and a "Featured Products" row resolved from a `searchSuggestions` promise via `<Suspense>`/`<Await>`. Used by both `HeaderSearch.tsx` (inline desktop dropdown) and `PageLayout.tsx`'s `SearchAside` (mobile aside) so the two search UIs share one suggestions implementation. Data comes from `app/lib/searchSuggestions.ts` (`SEARCH_SUGGESTIONS_QUERY`, best-sellers filtered through `EXCLUDE_HIDDEN_PRODUCTS_QUERY` like the homepage), fetched deferred in `root.tsx`'s `loadDeferredData` (`storefront.CacheLong()`) so it never blocks TTFB. Renders on every route (hidden until search is focused) — the product thumbnail uses Hydrogen's `<Image sizes="120px">`, not a raw `<img>`, since an unsized one was pulling full-res source images site-wide on every page load | |
| `CollectionCategoryNav` | `app/components/CollectionCategoryNav.tsx` | "Categories" block for the shop sidebar — collections as a vertical list with thumbnail/name/count. Passed into `<CollectionFilters categoriesSlot={...}>` (not rendered as its own sibling) so `CollectionFilters` controls the fixed sidebar order **Price → Categories → Availability**. Returns only a `.fblock`, no wrapper of its own — it renders inside `CollectionFilters`'s `.filters-content` div, so nesting that class again would double it up. `activeHandle` prop highlights the collection currently being viewed (`collections.$handle.tsx` passes `collection.handle`; `collections.all.tsx` passes none). Replaced the old horizontal `.category-row`/`.category-card` strip that used to render above the product grid on both collection routes — that CSS was deleted as dead code once the last usage moved into the sidebar. Thumbnail (`.sidebar-category-img`, 40px) renders via Hydrogen's `<Image sizes="40px">`, not a raw `<img>` — was pulling the full-res collection source image | |
| `SortDropdown` | `app/components/SortDropdown.tsx` | `?sort=featured\|newest\|price-high\|price-low` control, mounted on both collection routes. `featured` is the default on both and is listed first — see [[../../meta/decisions-log\|ADR-0007]] for what it maps to per route | |
| `CollectionFilters` | `app/components/CollectionFilters.tsx` | Renders a `Filter[]` (Availability, Price, plus any store-configured facet) as checkboxes + a dual-thumb price range slider, via [[utils\|collectionFilters.ts]]. Its root `.filters-content` is what's actually styled (not `.shop-sidebar`), so it looks identical whether it's mounted in the desktop `.shop-sidebar` or the mobile `.mob-filter-drawer`. Render order inside is fixed: **Price → `categoriesSlot` → Availability/other list filters → Clear all** — `categoriesSlot` is an optional `ReactNode` (`CollectionCategoryNav`) the caller passes in, so this component doesn't need to import collections/routing itself. Used on both `collections.$handle.tsx` (real Shopify `Collection.products.filters`) and `collections.all.tsx` (the top-level `products` query has no `filters` argument, so `buildLocalFilters`/`applyLocalFilters` in `collectionFilters.ts` compute/apply the same Availability+Price facets locally from the fetched product set) | |
| `TestimonialsMarquee` | `app/components/TestimonialsMarquee.tsx` | Homepage review marquee. **Cards and headline come from different sources on purpose:** the cards are the 17 curated reviews hardcoded in `lib/reviews.ts` (chosen for their customer photos, which live in `public/review-images/`), while the `rating` prop carries a store-wide `RatingSummary` aggregated from every product's `reviews.product_reviews` metafield — 166 reviews as of 2026-09-01, not 17. Falls back to summarising its own cards when no `rating` is passed, so it still renders standalone. Section `heading` is merchant-editable ([[homepage-content]]) | |
| `ContactBanner` | `app/components/ContactBanner.tsx` | Homepage footer contact panel — a single "General inquiries" column (email only — the phone was removed 2026-08-31, the shop has no phone line). The second "Workshop" column with the street address was removed 2026-08-31: the shop has no UK workshop or showroom to visit. Heading/subheading/CTA label come from the `home_page` metaobject via an optional `content` prop | |
| `CraftmanshipProcess` | `app/components/CraftmanshipProcess.tsx` | "Craft wood Furniture" process section — heading block, workshop photo and the step cards, all from the `home_page` metaobject via an optional `content` prop ([[homepage-content]]). **Two steps as of 2026-09-01** (Rough-cut, Drawn & marked); "Jointed by hand" and "Oiled & finished" were retired, so `.demo-process-grid` is a single column and the stacked pair matches the photo's height exactly. Step icons are hand-drawn SVGs in `ProcessIcons.tsx`, resolved from a stored key through `PROCESS_ICONS`; adding one means updating that map, the `ProcessIconKey` union **and** the `icon` field's `choices` validation — and retiring one means removing it from the union, which is what makes the page drop stale metaobject entries | |
| `ProductImage` | `app/components/ProductImage.tsx` | Single product image via Hydrogen `<Image>`, `aspectRatio 1/1`. `sizes` defaults to `(min-width: 45em) 50vw, 100vw` — **override it wherever the image renders small.** The PDP thumbnail rail passes `88px`; without it each of the 6 thumbs pulled a ~700px file for an 88px slot | |
| `ProductForm` | `app/components/ProductForm.tsx` | PDP variant options (swatches/dropdown/length-slider), upsell option rows, and the CTA row (qty stepper + `AddToCartButton` + wishlist heart). `quantity`/`onQuantityChange` are controlled props — state lives in `products.$handle.tsx` and is threaded into `cartLines` so it scales the main variant line and any selected upsell lines together | |
| `Breadcrumbs` | `app/components/Breadcrumbs.tsx` | Shared `.crumbbar`/`.crumb`/`.crumb-here` trail (styling in `app.css`, previously hand-written only in `products.$handle.tsx`). Takes `items: {label, to?}[]` — "Home" is always prepended; the last item renders as plain text (`.crumb-here`) even if it has a `to`. Mounted at the top of `.archive-page` on every content route except the homepage/landing pages: `products.$handle`, `collections.$handle`, `collections.all`, `collections._index`, `blogs._index`, `blogs.$blogHandle._index`, `blogs.$blogHandle.$articleHandle`, `contact`, `about`, `pages.$handle`, `policies.$handle`, `search`. Deliberately **not** on `policies._index` (still an unstyled scaffold page — no `.archive-page`/`.archive-wrap` to anchor it in) or on `_index`/`landing-oak`/`coming-soon`/`account.*`/`cart.*` | |
| `ArticleCard` | `app/components/ArticleCard.tsx` | Shared `.art-card` (image, date, title, "Read more") — extracted from a component that used to live only in `blogs.$blogHandle._index.tsx`. `ArticleCardData` is a loose structural type (`{handle, title, publishedAt, image?, blog:{handle}}`) so it accepts either the generated `ArticleItemFragment` or a route's own inline GraphQL fragment shape without needing a shared `.graphql` fragment file. Used by `blogs._index.tsx` (the Journal feed), `blogs.$blogHandle._index.tsx` (per-blog listing), and `blogs.$blogHandle.$articleHandle.tsx`'s "You may also like" strip | |
| `PaginatedResourceSection` | `app/components/PaginatedResourceSection.tsx` | Wraps Hydrogen's `<Pagination>` with Previous/Next links. **Grid classes must go through its `resourcesClassName` prop, never a `<div className="...">` wrapped around the whole component** — without `resourcesClassName`, the component's own outer `<div>` (holding PreviousLink + items + NextLink) becomes the wrapping element's only child, so a grid class on that wrapper never reaches the actual item cards and they fall back to stacked block flow. See `collections.$handle.tsx`'s `resourcesClassName="pgrid"` for the correct pattern | |
| `EditToolbarProvider` | `app/components/EditToolbarProvider.tsx` | Holds one page's inline-copy state for the [[../edit-toolbar\|edit toolbar]] — draft values, 800ms-debounced autosave, publish/reset. Takes `initialState` from the route loader (`loadPageContentState`), which is what keeps published copy server-rendered and stops the toolbar flashing in. `useEditToolbar()` returns **null** outside a provider, on purpose | |
| `EditToolbar` | `app/components/EditToolbar.tsx` | The floating admin bar (Edit on/off · Publish · Reset + status dot). Renders `null` for anyone who is not an allowlisted admin, so a shopper never receives the markup. Styled with `.edit-toolbar-*` in `app.css` | |
| `EditableText` | `app/components/EditableText.tsx` | One editable string: `field` (permanent dotted id) + `children` (the value the metaobject/defaults resolved to). Plain tag unless an admin has Edit on; then `contentEditable`, written imperatively so the caret does not jump, `preventDefault` on click so editing copy inside a `<Link>` cannot navigate away. Outside a provider it is just the tag — which is why `HeroCarousel` etc. still work on `landing-oak` | |
| `ConfirmDialog` | `app/components/ConfirmDialog.tsx` | Small `alertdialog` (Escape + a real scrim `<button>` to dismiss, not a click handler on a div). Currently only the toolbar's Reset confirmation | |
